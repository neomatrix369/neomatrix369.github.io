Section 01

The Superlinked Platform

One open-source inference cluster for every small model an agent calls — plus a hosted Cloud and an MCP edge

Three Surfaces, One Engine

Surface 1 · Open source

SIE (self-hosted)

Apache 2.0 inference server + production cluster. Encode, Score, Extract, Generate through one API. OpenAI-compatible endpoints. Laptop → Kubernetes with the same image.

77 docs pages · Helm + Terraform (GKE/EKS/AKS/ACK) · 3,360 ★ · 317 forks · 18 open issues

Surface 2 · Managed

SIE Cloud

Same API, no cluster. Sign up at console.superlinked.com, get an API key, $20 in credits. SOC 2 Type 2, US/EU endpoints, inference-grant programme for selected projects.

api.superlinked.com (us-east-2) · eu.api.superlinked.com · keys sk-sie-… · credit-priced per model · marketed as SIE Serverless (launch pending) · docs: Cold starts & SIE Relay

Surface 3 · Agent edge

SIE MCP server

Self-hostable MCP server (packages/sie_mcp) that offloads document conversion, image description, doc-QA, summarisation, NER and PII masking from Claude / any MCP client to your cluster — saves agent tokens.

Section 02 · Primitives

Encode · Score · Extract · Generate

Four verbs, one SDK, 100+ swappable models · plus the task layer built on top of them

The Four Primitives

Encode

Vectors

Dense, sparse (SPLADE/bge-m3), multi-vector (ColBERT/ColQwen), multimodal (SigLIP/CLIP), Matryoshka + int8/binary quantisation, MUVERA.

POST /v1/encode/:model · /v1/embeddings

Score

Rerank

Cross-encoders (bge-reranker-v2-m3, Qwen3-Reranker 0.6B/4B, R3), multi-vector late-interaction scoring, image+text rerankers (Qwen3-VL-Reranker).

POST /v1/score/:model · /v1/rerank · /v2/rerank

Extract

Structure

Zero-shot NER (GLiNER 2.x/2.5, NuNER), relations (GLiREL), classification (GLiClass, NLI), vision (Florence-2, OWLv2, Grounding DINO), OCR (LightOnOCR, GLM-OCR, MinerU, PaddleOCR-VL, docling), audio (Whisper).

POST /v1/extract/:model · /v1/audio/transcriptions

Generate

Text

Open LLMs via SGLang/MLX: Qwen3.8-27B-FP8, Qwen3.6-27B, Qwen3.5-4B, Gemma 4, Qwen3-0.6B. Tool calls, JSON-schema/regex/grammar output, streaming, LoRA per request.

POST /v1/generate/:model · /v1/chat/completions · /v1/responses

sie_sdk · one client, four verbs
from sie_sdk import SIEClient
from sie_sdk.types import Item

c = SIEClient("http://localhost:8080")   # or api.superlinked.com + API key

v = c.encode("sentence-transformers/all-MiniLM-L6-v2", Item(text="Hello"))
s = c.score("cross-encoder/ms-marco-MiniLM-L-6-v2",
            Item(text="What is ML?"),
            [Item(text="ML learns from data."), Item(text="Sunny today.")])
e = c.extract("urchade/gliner_multi-v2.1",
              Item(text="Tim Cook is the CEO of Apple."),
              labels=["person", "organization"])
g = c.generate("Qwen/Qwen3-0.6B", "Capital of France, one word.",
               max_new_tokens=16, temperature=0.0)
Shapes you get back
v["dense"].shape → (384,) s["scores"][0] → {'item_id':'item-0','score':-7.1,'rank':0} e["entities"][0] → {'text':'Tim Cook','label':'person','score':0.992,'start':0,'end':8} g["text"] → 'Paris' (+ finish_reason, usage, ttft_ms)
Wire format: msgpack by default; send Accept: application/json for JSON. /v1/generate wants the SIE-safe id (Qwen__Qwen3-4B-Instruct-2507); the SDKs convert slashes for you.

SIE Relay & Cold Starts (new SIE Cloud docs section)

The first page in the docs' new SIE Cloud section. Dedicated GPU capacity can scale to zero; while it restarts, SIE Relay may answer through a vetted inference partner instead of making you wait.

QuestionAnswer (docs, 14 Oct)
When is a request relayed?Only before dedicated capacity accepts it (never runs twice), when the model has scaled to zero or is starting. Same validation, same response format, same price; latency and output "can differ slightly".
Never relayedEmbedding and rerank requests (Relay serves only generation and extraction) · requests with X-SIE-Remote: forbid · org opted out · named dedicated profiles · grammar-constrained structured output · batch/jobs APIs · no partner in your key's region.
Relay-only modelsSome models/profiles are served only via Relay and labelled so in the console (e.g. zai-org/GLM-5.3-Flash:relay in the OpenCode example).
Who served it?Headers X-SIE-Served-By (local/remote), X-SIE-Upstream (sie-relay), X-SIE-Fallback-Reason (provisioning), X-SIE-Fallback-Error. SDK ≥ 0.10.0 exposes them as result["request"] (served_by, upstream, …) / result.request.
Data handling"Partners state that they keep no copy of the requests". Availability is per region; an unpinned key is checked against the deployment that receives the request.
 
from sie_sdk import SIEClient

# Every request from this client stays on dedicated capacity
client = SIEClient(
    "https://api.superlinked.com",   # be explicit (v0.10.1 hosted fallback)
    api_key=os.environ["SIE_API_KEY"],
    remote="forbid",                 # sends X-SIE-Remote: forbid
)
r = client.generate("Qwen/Qwen3.5-4B", "…", max_new_tokens=64)
print(r["request"].get("served_by"))   # "local" expected
Opt-outs: client option remote="forbid" (client-wide — there is no per-call option, so use a second client) · org-wide in console Settings → SIE Relay (owners/admins), after which relay-only models answer 403 THIRD_PARTY_SERVING_DISABLED.
Cold-start behaviour without Relay: 503 PROVISIONING + Retry-After (5–300 s on native endpoints, ≤ 60 s on OpenAI-compatible ones). SDKs wait up to 900 s by default (provision_timeout_s / provisionTimeout). v0.10.1: Python makes one final attempt after the last wait, so it can overshoot the budget by one attempt timeout.
AgentVetter implication (my reading): scanner findings and skill text can be sensitive. Set remote="forbid" on the router's SIE client, log served_by next to the existing timing headers, and keep Model Studio as the only intentionally external hop. Default is on, so today a cold start could route router traffic to a partner.
