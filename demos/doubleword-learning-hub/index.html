What the numbers actually say ↻ replaces v5's guessed discounts

Tier discounts (list price, 31 models with realtime)

  • Async ≈ 25% below realtime, tightly clustered (24–25% for the middle half).
  • Batch ≈ 50% below realtime, and ≈33% below async.
  • So the large savings in the marketing ("up to 90%") come from model choice (open-weight vs closed), not from tier choice alone. Output price spans 141× across the catalog ($0.10 to $11.25 per 1M async output).

Cache read is not always a discount

  • 29 models have a cache-read discount: median 80% below input (range 27–97%).
  • 7 models price cache read at the input price: Hy3, Qwen3.6 35B A3B, Gemma 4 31B IT, the three OCR models and Qwen3 Embedding 8B. The docs don't say whether caching is unsupported there or simply undiscounted.

Anomalies worth checking before you budget

  • Qwen3.5 9B dottxt: async output $0.70 and batch $0.58 are higher than realtime output $0.30. Could be a typo or real; confirm in the Console.
  • 5 models have no realtime price: Qwen3.5 4B, Qwen3.5 397B dottxt, DeepSeek OCR 2, LightOnOCR 2, olmOCR 2.
  • Embedding output is $0.00; you pay input only.
  • Reasoning table covers 19 of 36. Not listed: Kimi K3, Inkling, Hy3, MiMo V2.5 Pro, DeepSeek V4 Pro 0813 and V4.1 Flash, Qwen3.8 27B, Muse Glimmer, Gemma 4 26B and others. The DeepSeek V4 Flash page lists efforts, so the table may simply lag the catalog.

Prompt caching: implicit and explicit ↻ v5 described only a sliver

  • Implicit: on by default for cache-supported models, no code change. Best-effort; reused tokens bill at the cache-read rate; no write charges.
  • Explicit: add cache_control: {"type":"ephemeral","ttl":"5m"|"1h"} to a content block or tool. Guaranteed reads, sliding TTL, up to 4 breakpoints, shared across an org's keys. Minimum prefix is model-specific (1,024 tokens on most).
  • Write prices: 1.25× input (5m), 2× input (1h). Cache read = r × input, model-specific.
  • Models without caching ignore markers and bill normally, so markers are safe to send.

Reasoning effort ↻ v5's example and model list were wrong

  • Seven levels: none, minimal, low, medium, high, xhigh, max (OpenAI-compatible). v5 showed three.
  • Chat Completions: reasoning_effort. Responses: reasoning.effort.
  • Unsupported effort is rejected, not silently changed. Omit the field for the model default.
  • Some models map effort to a reasoning-token budget; your output limit must exceed it or the request is rejected.
  • Send only these OpenAI-style fields. Do not send thinking, thinking_token_budget or chat_template_kwargs.
  • Qwen3 non-thinking: append /no_think to the latest user prompt; it is Qwen-specific, not an effort value.
  • Anthropic thinking config is mapped to reasoning effort (Anthropic page).

  -H "Content-Type: application/json" \

    "model": "deepseek-ai/DeepSeek-V4-Flash",
    "messages": [{"role":"user",
      "content":"Solve this carefully."}],
    "reasoning_effort": "medium",

Anthropic API compatibility ↻ setup and scope corrected

from anthropic import Anthropic
client = Anthropic(
    base_url="https://api.doubleword.ai",  # no /v1
    auth_token=KEY)       # NOT api_key=
m = client.messages.create(
    model="deepseek-ai/DeepSeek-V4-Flash",
    max_tokens=1024,
    messages=[{"role":"user","content":"Hi"}],
    extra_body={"service_tier":"flex"})  # optional

api_key= makes the SDK send x-api-key; Doubleword authenticates on Authorization: Bearer.

  • Works: messages, streaming, GET /v1/models in Anthropic shape (with anthropic-version), flex tier via service_tier: "flex" in extra_body, caching on /v1/messages.
  • Batch: native /v1/messages/batches is not available. Use the OpenAI-format Batch API with "url": "/v1/messages" on every JSONL line and endpoint="/v1/messages"; results come back as Anthropic messages.
  • Anthropic's auto / standard_only service tiers are accepted but do nothing.
  • The page does not mention tool use or vision. v5 claimed tool use; that was not supported.
Contradiction (D2): this page says flex is "queued to the inference daemon, ~1 hour SLA, at batch pricing". The async page says work "starts within a minute" and is priced above batch. Both can't be right.
